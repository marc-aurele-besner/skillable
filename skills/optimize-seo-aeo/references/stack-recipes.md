# Stack recipes

Where metadata, sitemap, robots, JSON-LD, and `llms.txt` live in each stack. Prefer what the project already uses; check the installed framework version before choosing an API (`npm ls <pkg>` or the lockfile), since these move between majors.

```bash
rg -n -g '!node_modules' -e 'generateMetadata' -e 'export const metadata' -e 'useSeoMeta' -e 'useHead' -e '<svelte:head>' -e 'next-seo' -e 'react-helmet' -e 'application/ld\+json' -e 'sitemap' -e 'robots' .
rg --files -g '!node_modules' -g '*sitemap*' -g '*robots*' -g 'llms*.txt' -g '*manifest*'
```

## Next.js (App Router)

- **Metadata:** `export const metadata` / `generateMetadata` in `app/layout.tsx` and each `page.tsx`. Set `metadataBase: new URL(siteUrl)` in the root layout so relative OG/canonical URLs resolve. Title template: `title: { default: 'Brand', template: '%s · Brand' }`. Canonical: `alternates: { canonical: '/path' }`.
- **Sitemap:** `app/sitemap.ts` returning `MetadataRoute.Sitemap`; for large sites `generateSitemaps`. Build entries from the same data that drives `generateStaticParams`.
- **Robots:** `app/robots.ts` returning `MetadataRoute.Robots`; branch on `process.env.VERCEL_ENV` (or the project's env) to block previews.
- **Icons / OG image:** `app/icon.*`, `app/apple-icon.*`, `app/opengraph-image.*` file conventions.
- **JSON-LD:** render `<script type="application/ld+json" dangerouslySetInnerHTML={{ __html: JSON.stringify(data).replace(/</g, '\\u003c') }} />` in the page (server component).
- **llms.txt:** `app/llms.txt/route.ts` returning `text/plain` (mark `export const dynamic = 'force-static'`), or a prebuild script writing `public/llms.txt`.
- **Not found:** `notFound()` and `app/not-found.tsx` (real 404).

## Next.js (Pages Router)

`next/head` per page plus defaults in `_app`; `next-seo` if installed. Sitemap/robots: `next-sitemap` if already present, otherwise `pages/sitemap.xml.ts` with `getServerSideProps` writing XML, or a postbuild script. Static data via `getStaticProps`.

## Astro

- **Metadata:** a `<SEO>`/`<BaseHead>` component in the layout taking `title`, `description`, `image`; `Astro.site` (set `site` in `astro.config`) for absolute URLs; canonical `new URL(Astro.url.pathname, Astro.site)`.
- **Sitemap:** `@astrojs/sitemap` integration (needs `site`). Filter non-indexable pages with its `filter` option.
- **Robots / llms.txt:** `src/pages/robots.txt.ts` and `src/pages/llms.txt.ts` endpoints returning `Response`; read content collections with `getCollection`.
- **Starlight:** `head` config and frontmatter `description`; check for an `llms.txt` plugin before writing one.

## Nuxt

`useSeoMeta` / `useHead` in pages, defaults in `app.vue` or `nuxt.config` `app.head`. `@nuxtjs/seo` (bundles sitemap, robots, schema.org, OG image) or `@nuxtjs/sitemap` / `@nuxtjs/robots` if installed; otherwise server routes `server/routes/sitemap.xml.ts`, `robots.txt.ts`. Set `site.url` in config.

## SvelteKit

`<svelte:head>` in `+layout.svelte` / `+page.svelte`, data from `+page.ts` `load`. Sitemap and robots as `src/routes/sitemap.xml/+server.ts` and `robots.txt/+server.ts` with `export const prerender = true`. Real 404 via `error(404)`.

## Remix / React Router v7

`meta` export per route (merge parent meta with `matches`). Resource routes `app/routes/sitemap[.]xml.ts`, `robots[.]txt.ts`, `llms[.]txt.ts`. JSON-LD in the route component or via `meta` `{ "script:ld+json": data }`.

## Gatsby

`Head` export per page (Gatsby 4.19+) or `react-helmet`; `siteMetadata` in `gatsby-config`. `gatsby-plugin-sitemap`, `gatsby-plugin-robots-txt` if present.

## Vite / CRA SPA (React, Vue, Svelte)

The big lever is rendering: `index.html` ships one shell for every route. Options, least work first: prerender routes at build (`vite-plugin-ssg`/`vite-ssg` for Vue, `vite-react-ssg`, `react-snap` for CRA), move to the framework's SSG/SSR mode, or keep the SPA and accept that only the home `<head>` is indexed well. Propose the option; do it only if it is contained. Sitemap/robots: static files in `public/` generated by a small prebuild script from the route table.

## Static site generators

- **Hugo:** `baseURL`, `title`, `params.description` in config; head partial `layouts/partials/head.html` (or theme override); built-in sitemap and `enableRobotsTXT = true` with `layouts/robots.txt`; `llms.txt` via a custom output format or a `static/` file.
- **Jekyll:** `jekyll-seo-tag` and `jekyll-sitemap` plugins; `url` in `_config.yml`.
- **Eleventy:** head include in the base layout; sitemap and robots as `.njk`/`.11ty.js` templates with `permalink: /sitemap.xml`; `eleventyComputed` for per-page data.
- **Docusaurus:** `url`, `tagline`, `themeConfig.metadata`, `themeConfig.image`; the classic preset ships a sitemap (`sitemap` option); frontmatter `description` and `keywords` per doc; `static/robots.txt`.
- **VitePress:** `head`, `description`, `sitemap.hostname` in config; `transformHead` for per-page OG; frontmatter per page.
- **MkDocs:** `site_url`, `site_description`; sitemap built in; Material theme `extra` and `overrides/main.html` for meta.

## Plain HTML

Edit each page's `<head>` directly; keep a shared snippet consistent. `robots.txt`, `sitemap.xml`, `llms.txt` as static files at the web root. If there are more than a handful of pages, a tiny build script that writes the sitemap from the file list beats hand-maintaining it.

## Python / Ruby / PHP / other server frameworks

Django: `django.contrib.sitemaps`, template blocks for `<title>`/meta. Rails: `meta-tags` gem if present, `sitemap_generator`. Laravel: Blade layout sections, `spatie/laravel-sitemap` if present. WordPress: defer to the installed SEO plugin (Yoast, Rank Math) and change its settings only by editing theme code the repo owns.
